# Directional Outcomes

Capability-gap reasoning targets the intended directional outcome, not exact reproduction of a missing material, component, process, file type, implementation, or earlier solution.

A request may expose that the current machine cannot reach an outcome with its existing machinery. The gap representation should preserve:

- the requested direction/purpose;
- the relevant constraints and environment;
- what current capabilities already cover;
- the smallest missing capability the current machine can justify identifying;
- uncertainty where that identification is still a hypothesis.

A later solution may change implementation, architecture, process, geometry, material, or form if the resulting creation still reaches the intended direction under the actual constraints.

This does not erase physical or technical limits. It prevents the machine from mistaking one familiar route for the outcome itself.
