## Correctness gap

The established low-level constraint families already honor `enabled: false` during their actual position/velocity solve functions. However, the mixed composer measures mount/joint residuals from normalized definitions, and the collision-isolation layer derives connected-component topology from normalized edges. That means a retained disabled definition can still influence convergence accounting or component collision suppression when callers use those lower-level entrypoints directly.

Run 009 does not silently rewrite those mature entrypoints mid-lane. Instead it adds a bounded additive activity gate as a truth-preserving front door.

## Change

Added `uc-constraint-activity-gate.js` and candidate `AXM-CAP-PHYSICS-CONSTRAINT-ACTIVITY-GATE`.

The gate:

- normalizes and validates all three existing constraint families;
- partitions normalized definitions into enabled and disabled sets;
- preserves disabled definitions and ids in returned evidence;
- delegates only enabled constraints to the existing mixed composer;
- when collision isolation is requested, delegates only enabled edges to component-topology discovery;
- therefore prevents disabled definitions from contributing stale convergence residuals or suppressing ordinary donor-core contacts;
- still requires disabled definitions to reference valid bodies, preserving source-integrity validation;
- executes through the established single donor-core integration path.

The physics capsule now exports this route as `constraintActivityGate`.

## Regression evidence

`constraint-activity-gate-selftest.js` covers:

1. three disabled families produce zero active constraints and zero isolation components;

3. disabled mount/joint/limit residuals do not appear in delegated convergence diagnostics;
4. disabled definitions do not pull a separated dynamic body;
5. an enabled mount still creates component isolation while disabled sibling constraints remain inert;
6. a disabled definition with a missing body still fails source-integrity validation;

## Truth boundary

This is an additive safe front door, not a silent semantic rewrite of the existing lower-level composer or isolation modules. Direct callers of those lower-level modules retain their compatibility behavior; callers that retain disabled definitions and require them to be physically/topologically inert should use the activity gate.

Still not claimed:

- angular inertia or rotation-aware anchors;
- hinge, slider, rotational weld, motor or gear joint families;
- edge-only pair collision suppression (isolation remains component-wide for enabled edges);
- deformables, fluids or 3D physics;
- cross-engine deterministic equivalence;
- scientific validation.
