## Change

Added bounded **translation mounts** as an additive UC physics capability.

A translation mount preserves the full world-axis offset between two bodies:

`bodyB.position - bodyA.position = { x, y }`

This is intentionally different from a distance joint, which preserves only scalar separation. Translation mounts are useful for carried equipment, payloads, modular assemblies and kinematic carriers in the current translation-only donor architecture.

Implemented:

- deterministic mount normalization and id ordering;
- caller-owned fixed x/y offsets;
- inverse-mass position correction for one or two dynamic bodies;
- relative x/y velocity locking so a dynamic payload can inherit a kinematic carrier's translation velocity;
- bounded pre-core and post-core solve iterations;
- explicit `NO_DYNAMIC_MASS` receipts when both endpoints are immovable;
- separate core-stage world/evidence before post-mount stabilization;
- final-state checksum/diagnostic refresh;
- capsule export through `capabilities/physics-core/index.js`;
- candidate contract `AXM-CAP-PHYSICS-TRANSLATION-MOUNTS`.

## Truth boundary

Translation mounts are **not rotational weld joints**. Offsets stay in world axes and do not rotate with bodies because the preserved v0.3.1 donor core is translation-only and does not implement continuous rigid-body rotation or angular inertia.

Post-core projection can move bodies after donor-core collision/contact evidence was generated. Core events and contact geometry therefore remain explicitly labeled as describing the core stage before post-mount stabilization.

Connected mounted bodies can still collide unless caller collision filters suppress that pair.

Still not claimed:

- body rotation or angular inertia;
- rotating local anchors;
- hinge, slider, motor, gear or rotational weld joints;
- deformables, fluids or 3D physics;
- scientific validation.
