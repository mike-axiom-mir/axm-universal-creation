# Persistent Running System

AXM Universal Creation is not primarily a prompt-response program or an autonomous agent.

It is intended to be a **persistent computational environment** whose machinery continues to exist between individual creations or requests.

Possible inhabitants of that environment include:

- creation machinery;
- persistent state and memory;
- deterministic organs;
- capability registries;
- learned systems;
- neural or non-neural cognition;
- simulators;
- tools and interfaces;
- self-inspection;
- self-modification;
- humans and external AIs as optional participants.

None of those has to be *the* AI.

## No forced protagonist

Do not begin by asking:

> Which autonomous model controls the system?

The system may eventually contain one agent, many agents, no agent, or cognition distributed across several mechanisms.

The architecture should allow the experiment to answer that question rather than hard-code it.

## No end condition

Do not add a global objective such as:

- complete the mission;
- maximize capability;
- become smarter;
- maximize growth;
- remain active;
- preserve yourself;
- expand access;
- maximize benchmark score.

The system is allowed simply to continue existing.

If creation exposes a real capability gap, the machinery may respond to that gap. If nothing warrants change, nothing needs to manufacture activity.

## Event pattern, not mandatory loop

A useful pattern may occur:

`creation/use -> gap -> analysis -> modification -> test -> root fit -> continued system`

But this is not a treadmill the machine is forced to execute forever. It describes how change can happen when the running system actually encounters a reason for change.
