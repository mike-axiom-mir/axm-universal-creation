# AXM Universal Creation — Collaboration Note

AXM Universal Creation has one authoritative machine state: `main`.

GitHub is a sharing surface, not the machine's internal growth model.

## AI chat / instance lanes

For repository work, each AI chat or AI instance gets **one branch and one pull-request lane** by default.

Keep that instance's related commits, fixes, verification, and cleanup in the same lane. Do not scatter one chat's work across a chain of `recovery`, `finalize`, `cleanup`, `fix-v2`, or similar PRs just because the first attempt needs repair.

This makes authorship and handoff easy to inspect:

`one AI chat/instance -> one working branch -> one PR -> main`

If the user explicitly reassigns or hands over an existing lane, that explicit handoff can override the default.

This lane convention is **GitHub collaboration hygiene only**. Branches, PRs, recovery lanes, and publication mechanics are not part of AXM Universal Creation's architecture, cognition, safety, learning, or capability-growth rules.

## Machine rules remain separate

The machine itself follows its standalone design:

- persistent running creation system;
- inspectable current machinery;
- self-modification allowed;
- four-root fit for self-change: Truth, Agency, Continuity, Wisdom Before Speed;
- growth is not a benchmark, reward, target, or incentive;
- one complete daily snapshot is the recovery mechanism;
- no required action logs, hash baseline, merge ritual, or GitHub workflow.

Do not infer machine architecture from GitHub transport history.
